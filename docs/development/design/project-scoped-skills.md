# Project-scoped skills via `.agents/skills` indirection

## Problem

Every Cortex session loaded the full skill catalogue (127+ skills). There was no
per-project subset, no way to commit a declared set, and the existing skill install
path hard-coded a direct absolute symlink from the bundle into `~/.claude/skills/`.

Two gaps blocked project-scoped workflows:

1. **Storage convention mismatch.** The convention for projects that use multiple LLM
   tools (Claude, Codex, Gemini) is: real skill artifacts live in provider-neutral
   `<project>/.agents/skills/<skill>/`, with each provider dir (`.claude/skills/`,
   `.codex/skills/`, …) holding a *relative symlink* into `.agents`. The old Cortex
   code symlinked bundle source straight into `.claude/skills/`, bypassing `.agents`
   entirely.

2. **No declared source of truth.** Skills were enabled imperatively; nothing recorded
   "this project wants skills X, Y, Z" for a teammate to reproduce.

## Solution

A `.cortex/manifest.yaml` declares the project's skills; `cortex project sync`
reconciles it to the filesystem; the TUI gains drift detection and an inline mark
mode for bulk operations.

## Storage layout

```
bundle (cortex_root/skills/<name>)
   ── copy ──▶  <project>/.agents/skills/<name>/      real files, committable
   ── symlink ▶ <project>/.claude/skills/<name>  →  ../../.agents/skills/<name>
                  (other providers: .codex/skills/<name> → same .agents copy)
```

The **relative symlink** is load-bearing: it survives a `git clone` to any path and
avoids the absolute home-directory footgun that makes `~/.claude/…` symlinks break
for other users.

Global scope (`~/.claude/skills/`) is unchanged: a direct absolute symlink from the
bundle.

## Manifest schema

```yaml
# .cortex/manifest.yaml
skills:
  enabled: [systematic-debugging, atomic-commits]
# future: agents:, rules:, mcp:
```

Load/write via `core/manifest.py` which reuses `_load_yaml_dict` + PyYAML (already
a required dependency — no new dep).

## Module map

| Module | Role |
|--------|------|
| `core/skill_link.py` | `link_skill` / `unlink_skill` shared helpers; `DriftStatus` / `skill_drift_status` |
| `core/manifest.py` | `load_manifest` / `write_manifest` / `reconcile` |
| `cli.py` — `_build_project_parser` | `cortex project init/sync/status` |
| `cli.py` — `_handle_skills_move` | `cortex skills move <name> --to project\|global` |
| `tui/main.py` — `load_skills` | Drift field population on project scope |
| `tui/main.py` — `show_skills_view` | `⟳ stale` marker; `✓` mark badge |
| `tui/main.py` — mark mode | `x`/`e`/`d`/`m`/`esc` inline bulk ops |
| `tui/dialogs/skill_picker.py` | `SkillPickerScreen` + `build_skills_by_category` |

## Drift detection

Because `.claude/skills/<name>` resolves to the `.agents` *copy* (not the bundle),
the existing `check_installation_status` symlink-resolve compare would always report
`INSTALLED_DIFFERENT`. Instead, `skill_drift_status` compares the `.agents/skills/<name>`
directory tree against `cortex_root/skills/<name>` using `filecmp.dircmp` recursively.

## Key decisions

| Decision | Choice | Reason |
|----------|--------|--------|
| Storage | Copy bundle → `.agents` | Self-contained, committable; works offline |
| Symlink type | Relative (`../../.agents/…`) | Clone-portable; no absolute home paths |
| Global scope | Unchanged (direct bundle symlink) | No breakage risk; indirection not needed globally |
| Manifest format | YAML | `requires-python>=3.9` rules out stdlib `tomllib`; reuses PyYAML |
| Drift action | Copy refresh on `sync` | Copy can diverge; sync brings it current |

## Git recommendations for consuming projects

```gitignore
# Commit these — they are the source of truth:
# .cortex/manifest.yaml
# .agents/skills/

# Optionally commit (links are relative and survive clone):
# .claude/skills/

# Or ignore the derived symlinks (regenerated by `cortex project sync`):
.claude/skills/
```

The canonical choice is to commit `.cortex/manifest.yaml` and `.agents/skills/` and
ignore `.claude/skills/` (regenerable via `cortex project sync`).
